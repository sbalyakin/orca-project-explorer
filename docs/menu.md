# The right-click menu

It copies Orca's new-tab menu (search, icon row, agent rows with a chevron segment, setup flyout). Checked against a screenshot of Orca 1.4.261 on 2026-11-17.

## Orca sources to compare with

Under `~/Space/Development/_external/orca/src/renderer/src/components`:

- `tab-bar/create-menu/TabBarCreateRow.tsx` and `TabBarCreateRowIcons.tsx`: the search field, icon row, separators.
- `agent/AgentLaunchPickerMenuRow.tsx` and `AgentLaunchSetupSubmenu.tsx`: the agent row and its chevron segment (hover opens, click opens, `Right` opens, `Left` and `Escape` close).
- `agent/AgentLaunchSetupPanel.tsx` and `AgentLaunchSetupFooter.tsx`: the flyout (search, list, levels, prompt, buttons).
- `ui/menu-item.ts`, `ui/menu-surface.ts`, `ui/command.tsx`, `ui/button.tsx`, `ui/toggle.tsx`: the Tailwind classes behind every size, radius and state.
- Agent icons: `agent/icons/AgentIcon.tsx`, `agent-icon-glyphs.tsx`, `agent-favicon-assets.ts`, `status-bar/accounts/provider-icons.tsx`.

## Where the code and the screen disagree

- The source gives the model rows and the search field `h-9`; the screenshot shows about 30 px rows and a 40 px field. The plugin follows the screenshot. If Orca is updated, re-measure before trusting either.
- The composer box below the levels has no top border on screen although the source has one; the plugin follows the screen.

## Highlights in dark themes

The agent row (the split variant, `ui/menu-item.ts:81`), the model row (`ui/command.tsx`), the effort toggle and `Button` hover all use `--accent`, so the plugin uses `--orca-accent` too. In some dark themes (the user's, 2026-11-17) that is nearly the menu's colour, and Orca's own menu looks the same. A stronger white overlay was tried and reverted at the user's request: match Orca, not the contrast. Only `white/14` rows (`ROW_FOCUS`, the icon buttons) are a different Orca variant.

## Not reproducible with the plugin API

Browser and new-file icons, the gear, `Agent settings...`, row shortcut hints (`Cmd+Alt+T`), `No chat on this host`, and `/` and `@` in the prompt (the real one is Orca's chat composer). The panel's tooltips copy `ui/tooltip.tsx` (inverted bubble, arrow, 600 ms delay; `src/panel/tooltip.ts`, opt in with `data-tip`). They have no shortcut chips, since the panel has no shortcuts (checked live 2026-11-17: the bubble opens under the fold button, since there is no room above; not compared pixel by pixel). `pointerenter` fires inside the panel iframe (checked 2026-11-17).

## Flyout placement

A plugin cannot draw outside its frame. `placeFlyout` in `src/panel/menu.ts` puts the flyout right of the menu, else left, else over it at the panel edge (Orca does the same in a narrow window). It tracks its own height as the list loads.

Menu 288 px + flyout 416 px do not fit side by side in the usual sidebar, so "over it" is the common case (checked live 2026-11-17 at about 630 px). Then (`flyoutCovers`) two things differ from Orca on purpose (user request 2026-11-17): hovering the chevron does not open the flyout, since it would hide the menu under the pointer; and the flyout's search field starts with a back arrow instead of the magnifier, the only way back for a mouse (a click outside closes everything).

## Icons

`build.py` reads Orca's icon components and bundled PNG favicons and writes `src/panel/agent-icon-data.ts` (11 SVG glyphs, 33 PNG data URIs). It also writes `src/panel/lucide-data.ts`: every Lucide icon the panel draws (chrome icons and Orca's 20 project icons), taken from the `lucide-react` version in Orca's `pnpm-lock.yaml` (0.577.0, checked 2026-11-17) via `npm pack`; an icon that version lacks stops the script. A new chrome icon needs its Lucide name in `PANEL_LUCIDE` (`build.py`) and `PANEL_ICONS` (`src/panel/icons.ts`). Rerun it after updating the Orca checkout; set `ORCA_SRC` for another path. An agent with no icon gets a letter in a box, as in Orca. `currentColor` glyphs (Pi, OpenCode, Codex) follow the theme.

## The `+` menu (2026-11-18)

The header `+` opens a two-item menu (`showAddMenu`, `main.ts`): `Create new workspace` (Orca's own window, which picks the project itself) and `Create new tab`. The second replaces it with the workspace menu plus a project field above the agent search (`buildMainMenu({ project })`, list in `project-picker.ts`).

- The field's project is the open workspace's, else the selected row's, else none. With none, the terminal, open and agent items are off until one is picked.
- The target is the project's main checkout (`projectsOf` in `rows.ts`); linked worktrees are not listed (user decision). The list is a flyout like the model list, so it follows `placeFlyout` and has the same back arrow when it covers the menu.
- Checked live 2026-11-18: both menus open, the filter narrows the list, picking a project enables the items. No tab was launched during the check.

## The gear: Display options (2026-11-18)

The header gear opens a popover titled `Display options` (`src/panel/options-menu.ts`). Not compared pixel by pixel. The user checked the `Title` mode live on 2026-11-18 and it works. A submenu design (one row with a value and a flyout) was tried and replaced at the user's request by Orca's "Group by" segmented control, so `menu.ts` has no flyout extension for it.

- `Group by` (2026-11-18, user request; first section, `GroupMode` in `display.ts`, stored as `group`, unknown gives `folder`): `None` (flat list by name), `Folder` (default, the worker's tree), `Status` (sections `Permission`, `Unread`, `Working`, `Monitoring`, `Idle` by the strongest `Attention` in each project, empty ones hidden, projects by name). The panel regroups the worker's tree in `groupTree` (`grouping.ts`); the worker is untouched. Worktrees stay under their project in every mode. A section is a `group` node with `section: true`, drawn `title count chevron` (chevron right folded, down open; no folder mark, no status dot), folded state in `collapsed` under `status:<level>`. The filter never matches a section by its title (`filterNodes`), only the projects below it. In `None` and `Status` the folders above a project go into its tooltip (`folder`, set by `groupTree`). `Folders` and `Tree guides` show only for `Folder`; guides are also forced off in the other modes. Board status (`todo`, `in-review`) is not used (see `platform.md`). Not checked on the live panel.
- Every setting is drawn as Orca's segmented control (the `Group by` one is ours, with Orca's look), and `After project name` is the first of them: `SidebarGroupByToggle.tsx` (`ToggleGroup` outline, `sm`, `h-6`, `text-[10px]`, selected `bg-foreground/10 font-semibold`) in a `px-2 pt-0.5 pb-1` box under a `MENU_LABEL_CLASS` label (`ui/menu-item.ts`, `text-2xs` = 11px per `assets/main.css`). Segments `None`, `Branch` (default), `Title`; full names are the tooltip and `aria-label`. The window stays open after a pick, as Orca's does. Stored in `orca.storage` under `display:v1` (`parseDisplay`, `src/panel/display.ts`).
- `Folders` (2026-11-18, user request): what marks a group row. Segments `Arrows` (default), `Icons`, `Both`, `None` (`FolderMark`); old or unknown stored value gives `Arrows`. It only touches group rows. A hidden chevron or icon leaves no cell (user request 2026-11-18), so the folder's name moves left: `Arrows` and `Icons` by one cell, `None` by two. The indent per level is 20 for folders and projects in every mode (`INDENT`, user 2026-11-18), with no extra pull for projects in `None` (a 12 px pull was tried and dropped by the user). A workspace or project row never has an arrow cell, whatever `Folders` says (user request 2026-11-18); its own status is drawn in the indent left of the icon (`.status`, absolutely placed, so no text moves; at depth 0 the indent is only 8 px); the numbers are a guess at what looks right, checked on the user's screenshots only; the rolled-up status of a folded folder or project is drawn there too (user request 2026-11-18, replacing the right edge); a folded project also shows a muted icon (`.worktrees-mark`) right after its name to say worktrees are inside: `ChevronDown` when open, `ChevronRight` when folded (the user tried `ListChevrons…` and `ListCollapse` first and dropped them) (user request 2026-11-18); its `Open in…` button is now there like on any workspace row. Checked 2026-11-18 with `orca plugin shot local.project-tree --width 520` (it draws the live panel with the user's saved setting, here `None`): the status mark clears the icon at depth 1 and 2, the chevron after a project's name points down open and right folded. Not checked: `Both`, `Arrows`, `Icons` (the shot uses the saved choice; do not change it for a test). A workspace never sits at depth 0, since `folderPath` always gives at least one folder.
- The title (checked 2026-11-18): the host's `agents.list` leaves out native chats, so `agents.text` (`src/titles.ts`) reads `orca agent list --json`, which has terminal agents and chats with `title`, `lastAssistantMessage` and `updatedAt`. Its `worktreeId` is `<repo id>::<path>`; the path is matched to `workspace.list` rows (the panel's ids are `identity:...`) after `realPath` on both sides (`fs.realpath`, about 17 µs a call, measured 2026-11-18; symlinks such as `/tmp` -> `/private/tmp` are resolved; a folder that is gone keeps its path with trailing `/` removed by `normalizePath`). The symlink case is covered by a node test with a real symlink; not checked on the live panel. The agent that changed last wins. A fourth segment, `Message`, shows its last reply as one line (`oneLine`: line breaks to spaces, `*` and backticks dropped, cut at 240 characters; the row's ellipsis does the rest). Checked 2026-11-18 on the CLI: terminal agents often have an empty reply, chats usually have one, so the title and the reply are each taken from the newest agent that has one. `Message` needs the CLI: the `agents.list` fallback has titles only, so without the CLI the column is empty. `oneLine` also drops real `*` characters (`2 * 3` shows as `2 3`); a known cosmetic limit. Without the CLI the worker falls back to `agents.list` per workspace. Orca's plugin API has no "active tab" flag, so an idle shell tab gives nothing (not checked). Events `agent.status.changed` also set a title at once; the next `tree.load` replaces them. The CLI is started at most once per `TITLES_MIN_MS` (3 s; the last request runs after the pause), and an answer that is not the latest read is dropped (`titleSeq`). The last answer is kept in `orca.storage` (`texts:v1`, `parseTexts`) and drawn before the first read finishes, since a cold read takes seconds; a workspace that is gone is dropped by the next tree load (`pruneTitles`), and the fresh answer replaces the cache.
- `Density` (`compact`/`comfort`/`spacious`) sets the row height through `--row-height` on `.tree[data-density]` in `src/panel/style.ts`: 24 / 28 / 32px (2026-11-18). The old fixed 24px is now `compact`; the default is `comfort` (28px). Do not hard-code a row height.
