# Project Tree (Orca plugin)

Orca plugin `local.project-tree`: a project tree in the right sidebar with a right-click menu that opens a workspace, a terminal, or an agent. Usage is in `README.md`. What the code does not show lives in `docs/`.

## Read first

Before a task, read the `docs/` files its trigger names, then open code. Read `platform.md` before touching the manifest, the worker, module names or the dev loop.

| File | Read when |
|---|---|
| `docs/host-api.md` | Asked "can the plugin do X?"; adding an action that changes a workspace or a project; before you search Orca's source for a method |
| `docs/host-data.md` | Changing what `tree.load` returns, ids, project icons, agent status |
| `docs/tree.md` | Changing rows, the tree's node kinds, status marks, indent or guides |
| `docs/display-options.md` | Changing the Display options window or one of its settings: group by, text after the name, folder marks, tree guides, density |
| `docs/theme-font.md` | Changing panel colours, theme or font |
| `docs/menu.md` | Changing the menu, the flyout, icons, or comparing with Orca's own menu |
| `docs/launching.md` | Changing agent launch, model probes, the model cache, reasoning levels, or after an agent CLI update |
| `docs/platform.md` | Changing the manifest, worker, protocol or imports; a reload fails; the panel is blank; testing on the live panel; reading Orca's source |
| `docs/decisions.md` | Before adding a feature or reverting a choice; it lists what was rejected and what is unverified |

A doc is a starting point, not proof. Every fact has a date or a version; check the live file, command or Orca build before you rely on it, and fix the doc when reality differs. Orca's behaviour is read from the installed app (`platform.md`, `Machine environment`); the `_external/orca` checkout lags it.

## Layout

- `src/worker.ts`, `launch.ts`, `catalog/`: trusted worker (Node). Reads the host API, runs the `orca` CLI and the agents' own CLIs.
- `src/panel/`: the HTML panel (an iframe in Orca). `main.ts` wires state; `view.ts` and `layout.ts` draw rows and place their marks; `menu.ts` and `launcher.ts` draw the menu and the setup flyout.
- `src/types.ts` and `src/protocol.ts`: the one contract between the two halves. Change a request there first, then both sides.
- `src/panel/agent-icon-data.ts`, `lucide-data.ts`: generated by `build.py` from Orca's sources and its pinned `lucide-react`. Rerun the script, never edit the files.

## Commands

```sh
scripts/check.sh                      # tsc + `orca plugin test .`; run before every commit
git config core.hooksPath .githooks   # once per clone: the pre-commit hook runs check.sh
orca plugin logs local.project-tree   # first stop when the panel is blank
```

Orca reloads the plugin when its files change, so no manual reload is needed. `plugin shot` and live-panel testing are in `docs/platform.md`.

## Rules

- New non-trivial logic gets a node test beside it. The panel is covered only where it is pure (`rows.ts`, `grouping.ts`, `display.ts`, `layout.ts`); put new arithmetic or decisions there, not in `view.ts`, and check the rest on the live panel.
- Never put secrets in code or docs. Never close or delete a user's tabs, sessions or data except test tabs you opened.

## Keeping docs current

Update `docs/` in the same session that teaches you something lasting. Do not postpone it.

- **Filter:** would the next agent learn this by reading the code or the config? Then do not write it. Write what the code hides: a reason, a quirk of Orca or an agent CLI, what was tried and rejected, where the source of truth is, the exact text of an error with its cause and fix.
- **Where:** edit the file whose trigger fits. A new `docs/<topic>.md` only for a topic that fits none, with its row in the table above in the same edit. Split a file by `##` section when it passes about 8 KB (`wc -c docs/*.md`; lines here run long, so line counts mislead); never compress it by dropping facts. Break a bullet that runs past about 600 characters into sub-bullets.
- **How:** terse lists and tables. Identifiers, paths, commands and error texts in backticks. Date what can go stale: `(2026-11-17)`. After checking a fact on the live system, write `checked YYYY-MM-DD`.
- **In place:** change the fact where it lives; do not append a contradicting line. A cancelled decision keeps one line saying what was dropped and why, so nobody proposes it again. Close an open question by deleting it or turning it into a fact.
- **Conflicts:** newer data beats older; the live system beats any doc; a correction from the user applies at once.
- Machine-wide notes (Orca version on this Mac, shared paths, session findings) live in `~/Space/Development/various/docs/orca.md`; code facts live here.
